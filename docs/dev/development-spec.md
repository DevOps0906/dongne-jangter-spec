# 동네장터 개발지시서

| 항목 | 내용 |
|---|---|
| 문서 버전 | 0.1.0 (2026-10-24) |
| 대상 | 웹 구현 레포(`dongne-jangter-web`), Flutter 구현 레포(`dongne-jangter-flutter`), 스키마(`supabase/`) |
| 기준 문서 | `docs/planning/master-plan.md`, `docs/design/pattern-mapping.md`, `design/canvas/`, `tokens/tokens.json` |

## 1. 목표와 1차 범위

**목표:** 한 동네에서 이웃끼리 중고 물건을 사고파는 흐름을 웹과 앱 두 버전으로 만들어서 비교 검증합니다.

**1차 범위(포함)**
- 로그인(전화번호 OTP), 동네 설정(위치 권한 → 동네 인증 → 거래 범위)
- 상품 등록(사진 → 정보 → 가격·희망 장소), 임시저장, 판매 상태 변경
- 홈 피드, 검색, 상품 상세, 관심 목록
- 가격 제안, 채팅 목록, 채팅방(실시간)
- 거래 완료 후 매너 평가, 매너온도 표시, 판매자 프로필
- 동네생활(글·댓글·좋아요), 나의 메인, 판매·구매 내역, 설정(알림 토글, 로그아웃, 탈퇴)

**1차 제외**
- 결제, 안전결제, 배송
- 다크 테마, 다국어
- 관리자 화면, 광고
- 네이티브 푸시 알림 (웹은 PWA 설치 필요, 앱은 2차에서 검토)

## 2. 역할과 레포

| 레포 | 책임 | 하지 않는 것 |
|---|---|---|
| `dongne-jangter-spec` | 기획, 디자인, 토큰, 스키마, 이 지시서 | 앱 코드 작성 |
| `dongne-jangter-web` | Next.js 웹/PWA 구현 | 토큰 값 직접 수정, 스키마 직접 정의 |
| `dongne-jangter-flutter` | Flutter 앱 구현 | 토큰 값 직접 수정, 스키마 직접 정의 |

- 디자인 값과 스키마는 spec에서만 바꿉니다. 구현 레포에서 바꾸면 spec에 반영한 뒤 서브모듈을 갱신합니다.
- 두 구현 레포는 같은 라우트, 같은 화면 이름, 같은 상태 5종을 따릅니다.

**화면 수 기준:** 매핑 문서의 화면은 21개입니다. 이 표는 여기서 두 가지를 나눠 적었습니다.
- **판매·구매 내역**은 하나의 화면이지만 라우트가 두 개(`/my/sales`, `/my/purchases`)라서 행을 나눴습니다.

캔버스 보드 이름(예: `PhotoUpload`, `LocationSetup`)은 이 표의 화면에 대응합니다. 보드 이름과 라우트가 다르면 라우트 표를 따릅니다.

## 7. 공통 UI 규칙

1. **토큰만 사용합니다.** 색, 간격, 글자 크기, radius를 코드에 직접 쓰지 않습니다. 웹은 `var(--...)`, Flutter는 `AppColors`, `AppSpace`, `AppTextSize`를 씁니다.
2. **상태 5종을 모든 화면에 둡니다.** 기본, 로딩, 빈, 오류, 권한없음. 로딩은 스켈레톤을 씁니다.
3. **강조색은 화면마다 하나입니다.** 브랜드 오렌지는 주 행동 버튼, 현재 탭, 미읽음 표시에만 씁니다.
4. **반응형 3구간을 지킵니다.** 모바일 ~767, 태블릿 768~1199, 데스크탑 1200~. 글자 크기는 토큰 값을 씁니다.
5. **터치 영역은 44px 이상입니다.**
6. **숫자는 고정폭(tabular-nums)으로 씁니다.** 가격, 매너온도, 개수.
7. **문구는 짧고 다음 행동을 알려 줍니다.** 오류 문구는 무엇이 잘못됐고 어떻게 고치는지 씁니다.
8. **말투는 해요체입니다.** 예: "이 동네에 아직 올라온 물건이 없어요."

## 8. 데이터와 보안 규칙

1. **RLS를 끄지 않습니다.** 모든 테이블은 RLS가 켜져 있어야 하고, 정책 없이 열지 않습니다.
2. **service_role 키는 클라이언트 코드에 넣지 않습니다.** 웹도 Flutter도 anon 키만 씁니다. 서버 전용 작업은 Edge Function에서만 합니다.
3. **상품과 게시글 삭제는 soft delete입니다.** `deleted_at`을 채우고 목록에서 뺍니다.
4. **매너온도는 트리거로만 바꿉니다.** 클라이언트가 `profiles.manner_temp`를 직접 쓰지 않습니다.
5. **채팅은 참여자만 읽고 씁니다.** `is_chat_participant()`를 거칩니다.
