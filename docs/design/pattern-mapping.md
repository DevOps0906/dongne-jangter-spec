## 1. 7단계 분석 (`DASHBOARD_VISUAL.md` 1장 절차 적용)

| 단계 | 질문 | 중고거래마켓 판단 |
|---|---|---|
| 1 | 사용자가 왜 들어오나 | 동네 물건을 둘러보고 거래하려고. 원본 5장 "홈 고르기" 표에 소비자 마켓 행이 없다 → **홈은 C(KPI)가 아니라 피드(B)**. 이 판단은 제안 |
| 2 | 구조 | 2장 표 |
| 3 | 트레이딩 문법 적합도 | **부적합**. 숫자가 실시간으로 바뀌고 그 숫자를 보고 바로 행동하는 화면이 없다(채팅은 실시간이지만 숫자 의사결정이 아님). 원본 규칙대로 신규 제품은 5장 적합도 표에 먼저 추가한다 |
| 4 | 선택 기준 | 행동 빈도 하루 수회~수십 회, 레코드 수 많음(피드), 숙련도 초보·소비자 → **라이트 + 큰 CTA(V-E·V-F)** |
| 5 | 시각 아키타입 | 주: **V-E**(모바일 앱 화면, #16·#20·#71). 매너온도: **V-F**(단일 위젯). 상품 상세 이미지+가격: **V-M 일부**(가격 추이 차트 제외). 로그인·가격 제안: **V-K**(단계형 입력) |
| 6 | 가져오지 않을 것 | V-A 터미널(캔들·호가), V-I 글로우(앱 셸 금지), 크립토 네온, KPI 카드 나열(C), 사이드바·⌘K·조직 전환, 표·일괄 작업·컴팩트 밀도(V-E 주의: B2B 관리 기능을 모바일에 그대로 넣지 않는다) |
| 7 | 색·숫자 규칙 | 5장 |

| 매너 평가 | `/review/write` | I | 2단계: 긍정·부정 → 키워드 선택 | V-E | — |
| 설정 | `/my/settings` | H | 섹션별 저장(알림 토글은 즉시 저장 + 토스트). 위험 영역(탈퇴)은 맨 아래, 확인 문구 입력 | V-E | 설정을 모달 여러 겹으로 열지 않음 |
| 로그인·인증 | `/login`, `/login/verify` | I | 전화번호(기본)·이메일·소셜 3탭 → OTP | V-E + V-K | — |
| 동네 설정·인증 | `/setup/location`, `/location/*` | I + 고유 | 온보딩 단계(권한 → 인증 → 범위) | V-E | — |
| 동네 지도 | `/location/map` | **고유** | 지도 + 범위 원 | V-E | 원본 8장: 같은 `고유` 화면이 두 제품에서 나오면 새 코드로 승격. 지금은 `고유`로 둔다 |

**쓰지 않는 패턴**
- **C**(KPI 오버뷰): 홈에 쓰지 않는다.
- **D**(칸반): 판매 상태(판매중 → 예약중 → 판매완료)는 칸반이 아니라 **상태 배지 + 선택 시트**로 바꾼다.
- **E, J, K, L, O**: 해당 화면이 없다.

## 4. 토큰 구조 (`DESIGN_SYSTEM.md` 6장 → Flutter 번역)

| 계층 | 원본 | Flutter (제안) |
|---|---|---|
| 원시 | `tokens.css` `@theme` | `AppPalette` (색 상수만, 화면에서 직접 참조 금지) |
| 의미 | `--color-brand`, `--color-surface` 등 | `AppTokens` (`ThemeExtension`): brand, brandSubtle, background, surface, text, textMuted, border, danger, success, warning, statusSelling, statusReserved, statusSold |
| 컴포넌트 | `--button-bg: var(--color-brand)` | 위젯은 `Theme.of(context).extension<AppTokens>()`만 참조 |

- 위젯 안에서 `Color(0xFF…)` 직접 사용 금지(원본: hex 직접 사용 금지).
- **라이트/다크 두 벌**을 처음부터 만든다. 기본은 라이트(소비자 앱).
- 밀도: 원본은 컴팩트/기본 두 밀도를 요구하지만 대시보드 기준이다. 소비자 피드는 **기본 밀도만** 두는 것을 제안한다.

## 5. 색·숫자 규칙 (`DASHBOARD_VISUAL.md` 6장)

| 규칙 | 적용 |
|---|---|
| 포인트컬러 화면당 1개 | 브랜드 오렌지는 CTA·선택 상태·현재 탭에만 |
| 글로우·그라데이션 | 앱 셸·목록에 금지. 온보딩 한 곳에만 허용 |
| 색만으로 전달 금지 | 상태 배지는 텍스트 필수("판매중·예약중·판매완료"). 매너온도는 숫자 + 아이콘 병기 |
| 숫자 | 가격·매너온도·조회수에 tabular 숫자(`FontFeature.tabularFigures()`) |

**기존 기획안과의 충돌 (수정 제안)**

| 기존 값 | 문제 | 제안 |
|---|---|---|
| `tempOrange = #FF6F0F` | 브랜드색과 hex가 같아 "브랜드색 vs 의미색" 구분이 사라진다 | 온도 구간색은 브랜드색을 쓰지 않는 별도 팔레트로 |
| `statusReserved = #FF9500` | 브랜드 오렌지와 색상 거리가 가까워 예약중 배지와 CTA가 섞인다 | 예약중은 파랑·노랑 계열 별도 토큰. hex는 대비 4.5:1 확인 후 확정 |

> 원본 규칙은 "브랜드색과 **상승·하락색**의 분리"다. 위 두 항목은 그 취지를 유추 적용한 제안이다.

## 6. 반응형 (모바일 ~767 / 태블릿 768~1199 / 데스크탑 1200~)

| 구간 | 레이아웃 | 피드 | 채팅 | 제목 / 본문 / 캡션 (제안) |
|---|---|---|---|---|
| 모바일 ~767 | 하단 5탭 | 1열 카드 | 목록 → 방 이동 | 20 / 15 / 12 |
| 태블릿 768~1199 | 하단 탭 유지 또는 레일 | 2열 | **2단**(목록 + 방, 원본 F의 3단을 축소) | 22 / 16 / 13 |
| 데스크탑 1200~ | 사이드 레일 | 3열 | 2단 + 상품 정보 패널 | 24 / 16 / 14 |

- 최소 기준 폭은 **360dp**(원본의 375px 규칙을 Flutter 단위로 번역). 페이지 전체 가로 스크롤 금지.
- 글자 크기 130%(`textScaler`)에서 레이아웃이 깨지지 않는지 검증한다. 원본의 "키보드 조작" 항목은 TalkBack·글자 크기 검증으로 바꿔 적용한다.
- 태블릿·데스크탑은 린 원칙에 따라 **MVP 이후**. 지금은 `LayoutBuilder` 분기점만 잡아두고 모바일을 먼저 만든다.

## 8. 구현 순서 (`DASHBOARD_PATTERNS.md` 8장 공용화 기준)

원본 원칙: **쓰이지 않은 패턴을 미리 구현하지 않는다.** 다만 A·B·H는 거의 모든 제품이 쓰므로 처음부터 공용 위젯으로 만든다.

| 순서 | 대상 | 이유 |
|---|---|---|
| 1 | `AppPalette` + `AppTokens` + 라이트/다크 테마 | 이후 모든 위젯의 전제 |
| 2 | A: `BottomNavShell` | 5탭 전체의 뼈대 |
| 3 | B: 카드 목록 + 필터 칩 + 5상태 | 홈·검색·동네생활·내역·관심이 공유 |
| 4 | G: 상세 페이지 뼈대 | 상품·게시글·판매자 프로필 공유 |
| 5 | I: 스텝 폼 | 등록·로그인·동네 설정·매너 평가 공유 |
| 6 | H: 설정 섹션 | 나의 중고거래마켓·설정 공유 |
| 7 | F: 채팅 | 고유 로직이 많아 마지막 |
